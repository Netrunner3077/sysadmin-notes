Информационная безопасность

Как защитить инфраструктуру от угроз: файрволы, аутентификация, шифрование и аудит. Глава 5 учебного курса.

Почему безопасность — это процесс

Безопасность — не кнопка, которую нажимают один раз. Это непрерывный процесс: обновления, мониторинг, реакция на инциденты. Даже самая защищённая система устаревает в тот же день, когда перестаёт обслуживаться. Администратор должен мыслить как злоумышленник — иначе он проиграет.

Конфиденциальность

Данные доступны только тем, кому положено. Шифрование, права доступа, аутентификация.

Целостность

Данные не изменены незаметно. Контрольные суммы, подписи, журналирование.

Доступность

Сервисы работают, когда нужны. Резервирование, защита от DDoS, отказоустойчивость.

«Безопасность — это не продукт, а процесс. Нельзя купить безопасность, можно только поддерживать её.»

Модель угроз

Прежде чем защищаться, нужно понять — от кого. Угрозы бывают внешние и внутренние, случайные и намеренные. Самая частая уязвимость — не хакер, а сотрудник, который открыл вложение из письма.

Основные типы атак

  • Фишинг — поддельные письма и сайты, выманивающие учётные данные.
  • Brute-force — перебор паролей по словарю или маске.
  • SQL-инъекции — внедрение кода в запросы к базе данных.
  • DDoS — перегрузка сервиса массовыми запросами.
  • MITM — перехват трафика между двумя сторонами.
  • Социальная инженерия — манипуляция людьми, а не машинами.
  • Ransomware — шифрование данных с требованием выкупа.

Принцип наименьших привилегий

Пользователь должен иметь ровно столько прав, сколько нужно для работы — и ни одним больше. Это золотое правило, к которому возвращаются снова и снова. Не давайте никому root или Administrator «на всякий случай».

Файрволы

Файрвол (межсетевой экран) фильтрует трафик по правилам: пропускает нужное, блокирует подозрительное. Работает на разных уровнях — от сетевого до прикладного.

Основные принципы

  • 1 Разрешать только то, что явно нужно
  • 2 Запрещать всё остальное по умолчанию
  • 3 Логировать отброшенные пакеты
  • 4 Регулярно пересматривать правила

Инструменты в Windows и Linux

Инструмент Платформа Особенности
Windows Defender Firewall Windows Встроенный, GUI + PowerShell
iptables Linux Классика, мощно, но сложно
nftables Linux Современная замена iptables

Аутентификация и доступ

Аутентификация отвечает на вопрос «кто вы?». Авторизация — «что вам можно?». Эти два понятия всегда идут рядом: сначала подтверждаем личность, потом проверяем права.

Факторы аутентификации

  • Знание — пароль, PIN, секретный вопрос.
  • Владение — смартфон, токен, смарт-карта.
  • Биометрия — отпечаток пальца, лицо, сетчатка.

MFA (многофакторная аутентификация) объединяет два и более факторов. Это на порядок надёжнее пароля и должно быть стандартом для любого административного доступа.

SSH-ключи вместо паролей

В Linux-мире стандарт — вход по SSH-ключам. Пара «приватный + публичный» надёжнее и удобнее пароля. Приватный ключ никогда не покидает вашу машину, а на сервере хранится только публичная часть. 

# Сгенерировать пару ключей (ed25519 — современный алгоритм)
ssh-keygen -t ed25519 -C "admin@example.com"

# Скопировать публичный ключ на сервер
ssh-copy-id user@server

# Зайти без пароля
ssh user@server

# Отключить вход по паролю в /etc/ssh/sshd_config:
PasswordAuthentication no

Совет: если пользуетесь паролями — храните их в менеджере (Bitwarden, KeePassXC) и включайте MFA. Один и тот же пароль на разных сайтах — самая частая причина массовых утечек.

Шифрование

Шифрование превращает читаемые данные в нечитаемые — и обратно, но только при наличии ключа. Без него злоумышленник, перехвативший трафик, увидит лишь случайный набор символов.

Симметричное и асимметричное

Симметричное

Один ключ для шифрования и расшифровки. Быстро, но нужно как-то безопасно передать ключ. Пример: AES.

Асимметричное

Пара ключей: публичный шифрует, приватный расшифровывает. Медленнее, но решает проблему обмена. Пример: RSA, ECC.

Гибридное

Асимметрикой обмениваются симметричным ключом сессии. Так работает TLS и весь HTTPS.

Где шифрование применяется

  • TLS HTTPS, почта, VPN — защита трафика
  • LUKS Полнодисковое шифрование в Linux
  • BitLocker Полнодисковое шифрование в Windows
  • GPG Шифрование файлов и подписи
  • SSH Шифрование удалённых сессий

Аудит и логирование

Если что-то случилось — вы должны узнать об этом из логов, а не от журналистов. Логи — глаза администратора. Без них инциденты расследуются «по ощущениям».

Что логировать обязательно

  • Входы и выходы пользователей (успешные и неудачные).
  • Изменения в правах доступа и учётных записях.
  • Запуск и остановка служб.
  • Работа с конфиденциальными файлами.
  • Изменения в правилах файрвола.
  • Ошибки приложений и системные сбои.

Задача Windows Linux

Базовая защита сервера

Универсальный чек-лист, который стоит пройти на любом новом сервере — независимо от того, Windows это или Linux.

  1. Обновить ОС и всё установленное ПО.
  2. Включить файрвол, оставить только нужные порты.
  3. Сменить пароли по умолчанию, отключить лишние учётные записи.
  4. Настроить SSH: только ключи, отключить root-логин.
  5. Включить автоматические обновления безопасности.
  6. Настроить резервное копирование (см. главу про бэкапы).
  7. Установить системы мониторинга и оповещения.
  8. Включить и проверить логирование.
  9. Ограничить доступ по IP, где возможно.
  10. Регулярно пересматривать правила и права.
«Есть два типа администраторов: те, кого взломали, и те, кто ещё об этом не знает. Разница лишь в скорости обнаружения.»

Практические команды

Минимум, который стоит помнить наизусть для быстрой проверки состояния безопасности системы. 

# Показать текущие правила файрвола
sudo ufw status verbose          # Ubuntu/Debian
sudo firewall-cmd --list-all     # RHEL/Fedora
netsh advfirewall show allprofiles   # Windows

# Проверить открытые порты и слушающие сервисы
ss -tuln                         # Linux
netstat -an                      # Windows

# Показать последние входы в систему
last                             # Linux
lastb                            # неудачные попытки

# Просмотреть журнал аутентификации
sudo journalctl -u ssh           # Linux
# Event Viewer → Windows Logs → Security   # Windows

# Найти файлы с небезопасными правами
find / -perm -o+w -type f 2>/dev/null
