Сети и протоколы

Как компьютеры находят друг друга, договариваются о правилах общения и передают данные без потерь. Глава 3 учебного курса.

Зачем сисадмину сети

Можно идеально настроить сервер, но если он не имеет доступа к сети — он бесполезен. Понимание сетей отличает уверенного администратора от новичка, который «нажимает кнопки по инструкции». Без сетей нет ни интернета, ни корпоративной инфраструктуры, ни облачных сервисов.

Связность

Устройства должны уметь находить друг друга. За это отвечают IP-адресация и маршрутизация.

Надёжность

Данные могут теряться, дублироваться, приходить не в том порядке. Протоколы решают эти проблемы.

Безопасность

Передача данных должна быть защищена. Шифрование, VPN и файрволы работают на сетевом уровне.

Модель OSI: семь уровней

Эталонная модель OSI описывает, как данные проходят путь от приложения на одном компьютере до приложения на другом. Каждый уровень решает свою задачу и общается только с соседними уровнями.

  • 7 Прикладной — HTTP, FTP, SMTP, DNS
  • 6 Представления — кодировки, шифрование, сжатие
  • 5 Сеансовый — установка и разрыв сессий
  • 4 Транспортный — TCP, UDP, порты
  • 3 Сетевой — IP, ICMP, маршрутизация
  • 2 Канальный — Ethernet, MAC-адреса, коммутаторы
  • 1 Физический — кабели, сигналы, разъёмы
«Не понимаешь, на каком уровне проблема — начинай снизу. Кабель, потом интерфейс, потом маршрут, потом приложение.»

Стек TCP/IP

На практике чаще используют не семь уровней OSI, а четыре уровня модели TCP/IP. Именно она лежит в основе интернета и современных локальных сетей.

Уровень TCP/IP Соответствие в OSI Протоколы
Прикладной 7, 6, 5 HTTP, DNS, SMTP, SSH
Транспортный 4 TCP, UDP
Межсетевой 3 IP, ICMP, ARP
Канальный 2, 1 Ethernet, Wi-Fi

IP-адресация

IP-адрес — это «почтовый адрес» устройства в сети. Без него невозможно отправить или получить пакет данных. Адреса бывают двух версий: IPv4 и IPv6.

IPv4 и IPv6

IPv4

32-битный адрес. Пример: 192.168.1.10. Всего около 4,3 млрд адресов — и они давно закончились.

IPv6

128-битный адрес. Пример: 2001:0db8::1428:57ab. Практически неисчерпаемое пространство.

NAT

Трансляция адресов: множество устройств локальной сети выходят в интернет через один публичный IPv4-адрес.

Частные диапазоны IPv4

  • 10 10.0.0.0/8 — крупные корпоративные сети
  • 172 172.16.0.0/12 — средние сети
  • 192 192.168.0.0/16 — домашние и офисные сети

Маска подсети и CIDR

Маска показывает, какая часть адреса относится к сети, а какая — к устройству внутри неё. Запись /24 означает, что первые 24 бита — это сеть, оставшиеся 8 — хосты. В подсети /24 помещается 254 устройства.

Ключевые протоколы

Протокол — это правила общения. Разные протоколы отвечают за разные задачи: одни находят адреса, другие передают файлы, третьи синхронизируют время.

Протокол Назначение Порт
HTTP / HTTPS Веб-трафик 80 / 443
DNS Преобразование имён в IP-адреса 53
DHCP Автоматическая выдача IP-адресов 67 / 68
SSH Безопасный удалённый доступ 22
RDP Удалённый рабочий стол Windows 3389
SMTP / IMAP Отправка и получение почты 25 / 143

Маршрутизация

Когда пакет покидает вашу машину, он должен понять, куда идти дальше. Этим занимаются маршрутизаторы — они читают таблицу маршрутов и передают пакет следующему узлу, пока тот не достигнет цели.

Что такое шлюз по умолчанию

Шлюз — это «дверь» из локальной сети в интернет. Обычно это адрес вашего роутера. Если пакет не знает, куда идти внутри сети, он отправляется на шлюз, а тот решает, что с ним делать дальше.

Статическая и динамическая маршрутизация

  • Статическая — маршруты прописаны вручную. Просто, но плохо масштабируется.
  • Динамическая — маршрутизаторы обмениваются информацией автоматически. Протоколы: OSPF, BGP, RIP.
  • BGP — «протокол интернета», связывает автономные системы провайдеров по всему миру.

Службы сети

В любой сети работают сервисы, о которых администратор должен помнить каждый день. Они делают инфраструктуру удобной и управляемой.

DNS

Превращает example.com в IP-адрес. Без DNS интернет пришлось бы запоминать по цифрам.

DHCP

Выдаёт устройствам IP-адрес, маску, шлюз и DNS автоматически. Настраивается один раз, работает для всех.

NTP

Синхронизирует время. Рассинхрон хотя бы в минуту ломает Kerberos, логи и сертификаты.

Диагностика сети

Когда что-то не работает, важно быстро локализовать проблему. Вот минимум команд, который должен знать каждый администратор. 

# Проверить доступность узла
ping 8.8.8.8

# Проследить маршрут до цели
tracert example.com      # Windows
traceroute example.com   # Linux

# Узнать IP по имени
nslookup example.com     # Windows
dig example.com          # Linux

# Показать активные соединения
netstat -an              # Windows
ss -tuln                 # Linux

# Проверить IP-конфигурацию
ipconfig /all            # Windows
ip a                     # Linux

Практический совет

Соберите домашнюю сеть из виртуальных машин — это лучший тренажёр. Две виртуалки в VirtualBox в режиме «Внутренняя сеть» и одна с NAT — и вы уже можете тренировать маршрутизацию, DNS, SSH, файрволы.

Совет: установите Wireshark и посмотрите, как выглядит реальный трафик. Одно дело — читать про TCP-рукопожатие, и совсем другое — видеть его пакеты вживую.
