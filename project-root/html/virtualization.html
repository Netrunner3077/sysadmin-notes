Виртуализация и контейнеры

Как запустить несколько систем на одном железе, чем виртуальная машина отличается от контейнера и почему Docker изменил индустрию. Глава 7 учебного курса.

Что такое виртуализация

Виртуализация — это технология, позволяющая запускать несколько изолированных операционных систем на одном физическом сервере. Каждая такая система называется виртуальной машиной (VM) и думает, что работает на настоящем «железе».

До виртуализации один сервер обслуживал одну задачу. Сегодня на одной стойке умещается десятки виртуальных машин — это экономит деньги, место и электроэнергию.

Экономия ресурсов

Один мощный сервер заменяет пять слабых. Загрузка CPU и памяти используется эффективнее.

Изоляция

Падение одной VM не затрагивает другие. Удобно для тестирования и разделения сред.

Гибкость

Виртуалку можно клонировать, перенести на другой хост или откатить к снапшоту за минуты.

Гипервизоры

Гипервизор — это программа, которая управляет виртуальными машинами и распределяет между ними физические ресурсы. По типу работы их делят на два вида.

Тип 1 (bare-metal)

Работает напрямую на железе, без хостовой ОС. Максимальная производительность, используется в дата-центрах.

  • VM VMware ESXi — промышленный стандарт
  • HV Microsoft Hyper-V Server — бесплатная версия
  • X Xen / XenServer — основа облаков
  • KVM Kernel-based Virtual Machine — встроен в Linux
  • PVE Proxmox VE — open-source решение на KVM

Тип 2 (hosted)

Работает как приложение поверх обычной ОС. Удобно для разработки и обучения, но уступает в производительности.

  • VB Oracle VirtualBox — бесплатный, кроссплатформенный
  • VW VMware Workstation / Fusion — платный, мощный
  • PL Parallels Desktop — популярен на macOS
  • HV Hyper-V в Windows 10/11 Pro — встроенный
«Для обучения достаточно VirtualBox. В продакшене работают на KVM, ESXi или Proxmox — там, где важна производительность.»

Виртуальная машина vs контейнер

До появления Docker путаница между VM и контейнерами была редкостью. Сегодня это, пожалуй, главный вопрос новичка. Ключевое отличие — что именно изолируется.

Критерий Виртуальная машина Контейнер
Что внутри Полная ОС + приложение Только приложение и его зависимости
Ядро Своё, отдельное Общее с хост-системой
Размер Гигабайты Мегабайты
Запуск Минуты Секунды
Изоляция Полная Частичная, на уровне процессов
Когда выбирать Разные ОС, жёсткая изоляция Микросервисы, CI/CD, тесты

Простая аналогия: виртуальная машина — это отдельная квартира со своей кухней и санузлом. Контейнер — комната в общежитии: своя кровать и шкаф, а кухня и душ общие с хост-системой.

Docker: контейнеры для всех

Docker — это платформа для упаковки, доставки и запуска приложений в контейнерах. Идея проста: приложение со всеми зависимостями собирается в образ, который запускается одинаково где угодно — на ноутбуке разработчика, в тестовой среде и в продакшене.

Ключевые понятия

Образ (Image)

Шаблон только для чтения. Содержит код, библиотеки, настройки. Строится по Dockerfile.

Контейнер

Запущенный экземпляр образа. Можно запускать десятки контейнеров из одного образа.

Реестр (Registry)

Хранилище образов. Docker Hub — публичный, можно поднять свой приватный.

Основные команды

# Скачать образ из Docker Hub
docker pull nginx:latest

# Запустить контейнер
docker run -d -p 8080:80 --name web nginx

# Посмотреть запущенные контейнеры
docker ps

# Остановить и удалить
docker stop web && docker rm web

# Собрать свой образ из Dockerfile
docker build -t my-app:1.0 .

# Залогиниться в реестр и запушить образ
docker login
docker push my-app:1.0

Плюсы Docker

  • «Работает у меня — работает везде» — единая среда.
  • Быстрый запуск и остановка приложений.
  • Изоляция сервисов друг от друга.
  • Экономия ресурсов по сравнению с VM.
  • Готовая экосистема образов на Docker Hub.
  • Легко масштабировать горизонтально.

Оркестрация: Kubernetes

Когда контейнеров становится десятки и сотни, нужен инструмент, который управляет ими автоматически. Здесь на сцену выходит Kubernetes (K8s) — стандарт оркестрации контейнеров.

Что умеет Kubernetes

  • 1 Автоматически распределять контейнеры по узлам
  • 2 Перезапускать упавшие контейнеры
  • 3 Масштабировать нагрузку по нагрузке
  • 4 Управлять сетью между контейнерами
  • 5 Хранить секреты и конфигурации
  • 6 Обновлять приложения без простоя

Когда K8s не нужен

Kubernetes — инструмент для крупных систем. Для одного-двух контейнеров его сложность не оправдана. Альтернативы проще:

Docker Compose

Запуск нескольких контейнеров на одной машине через YAML-файл. Идеально для dev-среды.

Docker Swarm

Встроенная оркестрация в Docker. Проще K8s, но менее функциональна.

Nomad

Альтернатива от HashiCorp. Запускает не только контейнеры, но и обычные приложения.

Где это применяется

Виртуализация и контейнеры сегодня везде — от домашних лабораторий до облаков на тысячи серверов. Несколько типичных сценариев.

Тестовая лаборатория

Домашний сервер с Proxmox позволяет развернуть Windows Server, Ubuntu Server и пару клиентских машин за час. Идеально для подготовки к сертификациям и экспериментов с сетью.

Разработка и CI/CD

Docker даёт разработчикам одинаковую среду на всех этапах: локально, на тестовом сервере, в продакшене. CI-пайплайны собирают образы и автоматически выкатывают их.

Микросервисная архитектура

Большие приложения разбиваются на десятки маленьких сервисов, каждый в своём контейнере. Kubernetes управляет ими как единой системой.

Облачные платформы

AWS, Azure, Google Cloud построены на виртуализации. Крупные провайдеры уже несколько лет предлагают managed Kubernetes — арендовать кластеры в один клик.

«Разработчик упаковал приложение в контейнер в пятницу вечером. В понедельник оно запустилось в продакшене так же, как у него на ноутбуке. Это и есть магия контейнеров.»

Практический совет

Соберите домашний стенд: Proxmox VE на старом компьютере или VirtualBox на текущем ноутбуке. Создайте виртуальную машину с Ubuntu, установите Docker, запустите пару контейнеров, объедините их через docker compose. Это даст практическое понимание, которое не заменят никакие книги.

Совет: прежде чем идти в Kubernetes, разберитесь с Docker и docker compose. K8s — это уже следующий уровень, и без базы он покажется набором магических YAML-файлов.
