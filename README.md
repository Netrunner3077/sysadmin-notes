## О проекте

**SysAdmin Notes** — это учебный веб-сайт, оформленный как последовательный курс
по системному администрированию. Сайт состоит из **девяти глав**, выстроенных
в логическую цепочку: от знакомства с профессией — до автоматизации и CI/CD.

Каждая глава опирается на предыдущую, а в конце каждой есть навигация
«предыдущая / следующая», как в книге.

Проект создан в образовательных целях и демонстрирует практическое применение
семантической вёрстки, модульной архитектуры CSS и адаптивного дизайна
**без использования JavaScript**.

**Выполнено** — flexbox является основной системой раскладки.

**Пример 1. Шапка сайта** (`css/header.css`):

```css
.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

**Пример 2. Меню навигации:**

```css
.nav-list {
  display: flex;

```

**Пример 3. Форма** (`css/forms.css`):

```css
.form {
  display: flex;

```

**Пример 4. Списки с иконками** (`css/list.css`):

```css
.osi-item {
```

#### Критерий 4. Есть форма

**Выполнено.**

- **Страница:** `html/auth.html`
- **Стили:** `css/forms.css`

Форма включает два режима (переключение через `:target`, без JS):

- **Вход:** email + пароль + «Запомнить меня»
- **Регистрация:** имя + email + пароль + согласие с условиями

Пример разметки:

```html
<form class="form" action="#" method="post" novalidate>
  <div class="form-group">
    <label class="form-label" for="login-email">Email</label>
    <input
      class="form-input"
      type="email"
      id="login-email"
      name="login-email"
      required
    />
    <span class="form-error">Введите корректный email</span>
  </div>
  <button class="btn btn-primary form-submit" type="submit">Войти</button>
</form>
```

Живая валидация реализована через `:user-invalid` и `:user-valid`:
невалидное поле подсвечивается красным, валидное — зелёным, сообщение
об ошибке появляется под полем.

## Технологии

### HTML5

- Семантические теги: `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`,
  `<footer>`, `<figure>`, `<figcaption>`, `<blockquote>`, `<pre>`, `<code>`
- Валидные HTML-сущности: `&amp;`, `&mdash;`, `&copy;`, `&larr;`, `&rarr;`,
  `&#9662;`

### CSS3

- CSS-переменные (`:root`) для единой цветовой схемы
- **Flexbox** — основная система раскладки (шапка, футер, списки, формы)
- **CSS Grid** — карточки, галерея, сетка футера
- Псевдоклассы: `:hover`, `:focus-visible`, `:user-invalid`, `:user-valid`,
  `:target`
- Псевдоэлементы: `::before`, `::after`, `::selection`, `::placeholder`
- Медиазапросы для адаптивности (768px, 600px, 900px)
- `@media (prefers-reduced-motion)` для доступности

### Без JavaScript

- Мобильное меню реализовано через **«checkbox hack»**
- Переключатель «Вход / Регистрация» — через псевдокласс `:target`
- Валидация форм — через `:user-invalid` и `:user-valid`

Проект не требует сборки, установки зависимостей или веб-сервера.

1. Скачайте папку проекта.

### Этап 1. UI/UX-улучшения (HTML + CSS, без PHP)

<details>
<summary><b>1.1. Тёмная тема</b></summary>

Реализация через CSS-переменные в отдельном `@media`. Цветовая схема
определяется системными настройками пользователя — JavaScript не нужен.

**Подход:**

- Все цвета уже вынесены в `:root` (`variables.css`) — это половина успеха
- В `@media (prefers-color-scheme: dark)` переопределяем значения переменных:
  фон, текст, границы, тени
- Опционально — кнопка ручного переключения (светлая / тёмная / авто)
  через ту же технику, что и «checkbox hack» для бургера, с сохранением
  выбора в `localStorage` (минимальный JS)

**Ожидаемый результат:** сайт автоматически адаптируется под тему ОС.

</details>

<details>
<summary><b>1.2. Хлебные крошки (breadcrumbs)</b></summary>

Навигационная цепочка под шапкой: **«Главная › Сети › Глава 3»**. Помогает
пользователю понять, где он находится в структуре курса, и быстро вернуться
на уровень выше.

**Компонент:** `<nav class="breadcrumbs" aria-label="Навигация по сайту">`

- Flexbox-строка с разделителями «›»
- На мобильных — обрезается до 2 последних уровней
- Ссылки — обычные `<a>`, текущий элемент — `<span aria-current="page">`

**Где использовать:** на всех главах курса и внутренних страницах.

</details>

<details>
<summary><b>1.3. Анимация появления секций</b></summary>

Секции плавно появляются при попадании в зону видимости — это делает
прокрутку «живой» и подчёркивает структуру материала.

**Реализация без JavaScript:**

- `@keyframes fadeInUp { from { opacity: 0; transform: translateY(20px); } to { opacity: 1; transform: translateY(0); } }`
- `animation-delay` рассчитывается вручную для каждой секции (0s, 0.1s, 0.2s…)
- Обёртывается в `@media (prefers-reduced-motion: no-preference)`, чтобы
  не раздражать пользователей с вестибулярными расстройствами

**Улучшенная версия (с минимальным JS):**

- `IntersectionObserver` отслеживает появление секций
- Класс `.is-visible` навешивается, когда секция попадает в viewport
- Анимация запускается ровно один раз, без перезапуска при скролле вверх
</details>

<details>
<summary><b>1.4. Продакшен-стилизация формы</b></summary>

Доведение страницы `auth.html` до уровня «не стыдно показать в портфолио»:

- Плавная подсветка `label` при фокусе на поле
- Иконки внутри `input` (email, пароль, «показать пароль»)
- Индикатор силы пароля (слабый / средний / сильный)
- Состояния «загрузка» и «успех» на кнопке
- Красивое сообщение об успехе / ошибке сервера
- Плавный переход между «Вход» и «Регистрация» (сейчас — резкий через
  `:target`), можно добавить slide-анимацию
- Кнопки соцсетей-заглушек (в будущем — OAuth)
</details>

<details>
<summary><b>1.5. Боковая панель (aside) с оглавлением</b></summary>

Ключевое улучшение навигации по длинным главам. Слева (на десктопе) появляется
**липкая панель** с оглавлением текущей главы: список параграфов, каждый —
якорная ссылка.

**Что даёт пользователю:**

- Не нужно скроллить наверх — все разделы под рукой
- Видно, где он находится (активный пункт подсвечивается)
- Плавный переход по якорю (`scroll-behavior: smooth` уже есть)

**Технически:**

- `<aside class="toc">` внутри `<main>`
- `position: sticky; top: 90px` — «прилипает» при скролле
- Flexbox-раскладка: `<aside>` + `<article>` рядом
- **На мобильных — выдвижная панель (drawer):**
  - Скрыта по умолчанию за пределами viewport (`translateX(-100%)`)
  - Кнопка «Содержание» в шапке открывает её через checkbox hack
  - Плавные `transition` по `transform`
  - Затемняющий оверлей позади панели

**Ожидаемый результат:** страницы курса превращаются в «документацию»
уровня современных docs-сайтов (как MDN или GitBook).

</details>

### Этап 2. Переход на PHP

<details>
<summary><b>2.1. Архитектура</b></summary>

Проект переводится с набора статических HTML-файлов на шаблонную систему
с общим layout и динамическими страницами.

**Ожидаемая структура:**

```text
project-root/
├── public/                 Корень веб-сервера
│   ├── index.php           Единая точка входа
│   ├── assets/             CSS, JS, изображения
│   └── uploads/            Загруженные пользователями файлы
├── app/
│   ├── controllers/        Логика страниц
│   ├── models/             Работа с БД
│   ├── views/              Шаблоны (layout, partials, страницы)
│   └── helpers/            Утилиты (auth, validation, flash)
├── config/                 Настройки БД, окружения
├── storage/                Логи, кэш, миграции
└── README.md
```

</details>

<details>
<summary><b>2.2. Шаблонизация</b></summary>

Общие элементы (header, footer, aside, breadcrumbs) выносятся в отдельные
подключаемые файлы:

- `app/views/partials/header.php`
- `app/views/partials/footer.php`
- `app/views/partials/breadcrumbs.php`

Контент глав — в шаблонах глав (`views/chapters/*.php`) или, что гибче,
в базе данных: страницы редактируются через админку без правки кода.

</details>

<details>
<summary><b>2.3. Конфигурация и безопасность</b></summary>

Минимальный набор практик, обязательных с первого дня:

- Отдельный файл `.env` с настройками БД (**не в Git!**)
- PDO с подготовленными запросами (никаких ручных конкатенаций SQL)
- CSRF-токены для всех POST-форм
- Хеширование паролей через `password_hash()` / `password_verify()`
- Валидация и санитизация входных данных на сервере
- Защита от XSS через `htmlspecialchars()` при выводе
- Разграничение прав (гость / пользователь / модератор / админ)
</details>

### Этап 3. Функционал на PHP

<details>
<summary><b>3.1. Административная панель</b></summary>

Отдельный защищённый раздел `/admin`, доступный только пользователям
с ролью «администратор».

**Возможности:**

- Управление контентом глав: редактирование текста (WYSIWYG или Markdown),
  вставка/замена изображений, изменение порядка разделов
- Управление пользователями: просмотр, изменение ролей, блокировка, удаление
- Управление комментариями и темами форума
- Системные настройки: название сайта, описание, контакты, цвета темы, логотип
- Журнал действий (audit log): кто, что и когда менял
- Резервные копии БД одной кнопкой

**UI:** тот же стиль, что и публичная часть — единый CSS, никакого
«админского вида». Переходы, карточки, формы — как везде.

</details>

<details>
<summary><b>3.2. Личный кабинет пользователя</b></summary>

Раздел `/account`, доступный авторизованным пользователям.

**Возможности:**

- Загрузка и обрезка аватара (например, через GD или Imagick)
- Смена никнейма с проверкой на уникальность
- Смена email с подтверждением по ссылке
- Смена пароля с вводом текущего
- Просмотр своей активности: комментарии, темы, прогресс по главам
- Настройки приватности (виден ли профиль другим)
- Удаление аккаунта с подтверждением

**Прогресс по главам:**

- Таблица `user_progress`: `user_id`, `chapter_id`, `completed_at`
- На странице главы — кнопка «Отметить как прочитанное»
- В личном кабинете — красивый прогресс-бар «Пройдено 5 из 9 глав»
</details>

<details>
<summary><b>3.3. Форум обсуждений</b></summary>

Современный форум, вдохновлённый Reddit, Discourse и Habr — в противовес
архаичным имиджбордам.

**Ключевые принципы:**

- Уважение к пользователю: аватар, ник, репутация, подпись
- Дерево обсуждений (nested comments), а не плоская лента
- Markdown-разметка в постах и комментариях
- Загрузка изображений с превью и оптимизацией
- Реакции (лайк, полезно, спасибо) вместо «плюсов и минусов»
- Модерация через жалобы + автоматические фильтры

**Сущности БД:**

| Таблица       | Назначение                                            |
| ------------- | ----------------------------------------------------- |
| `boards`      | Доски (разделы форума: Linux, Windows, Сети, DevOps…) |
| `threads`     | Темы внутри досок                                     |
| `posts`       | Сообщения внутри тем                                  |
| `comments`    | Комментарии к постам (с `parent_id` для дерева)       |
| `reactions`   | Реакции пользователей на посты и комментарии          |
| `attachments` | Прикреплённые файлы (изображения, документы)          |
| `reports`     | Жалобы на контент                                     |

**Функции:**

- Создание доски — только админ
- Создание темы — любой авторизованный пользователь
- Ответы, цитирование, упоминания через `@nickname`
- Закрепление тем, закрытие темы модератором
- Поиск по темам и постам
- Уведомления: «вам ответили», «вас упомянули»
- Подписка на тему (email или внутреннее уведомление)
- Сортировка: по новизне, по популярности, по активности
- Пагинация (без бесконечного скролла — он пугает часть аудитории)

**UI-принципы:**

- Никаких «бампов» и анонимных постов
- Аватары у всех, у модераторов — специальный бейдж
- Кнопка «Пожаловаться» — везде, где есть контент
- Счётчики репутации — прозрачные (видно, за что начислено)
</details>
