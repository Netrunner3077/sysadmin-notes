1. О ПРОЕКТЕ
--------------------------------------------------------------------------------

SysAdmin Notes — это учебный веб-сайт, оформленный как последовательный курс
по системному администрированию информационно-коммуникативных и операционных
систем Windows и Linux.

Сайт состоит из девяти глав, выстроенных в логическую цепочку: от знакомства
с профессией — до автоматизации и CI/CD. Каждая глава опирается на предыдущую,
а в конце каждой есть навигация «предыдущая / следующая», как в книге.

Проект создан в образовательных целях и демонстрирует практическое применение
семантической вёрстки, модульной архитектуры CSS и адаптивного дизайна без
использования JavaScript.

    ЭТАП 1. ВЫБОР ТЕМЫ И ПОДГОТОВКА
      За основу взята тема системного администрирования Windows и Linux.

      страницами.

9.2. ЭТАП 1. UI/UX-УЛУЧШЕНИЯ (HTML + CSS, БЕЗ PHP)
--------------------------------------------------------------------------------

9.2.1. ТЁМНАЯ ТЕМА

  Реализация через CSS-переменные в отдельном @media.
  Цветовая схема определяется системными настройками пользователя —
  JavaScript не нужен.

  Подход:
    - Все цвета уже вынесены в :root (variables.css) — это половина успеха.
    - В @media (prefers-color-scheme: dark) переопределяем значения
      переменных: фон, текст, границы, тени.
    - Опционально — кнопка ручного переключения (светлая / тёмная / авто)
      через ту же технику, что и «checkbox hack» для бургера,
      с сохранением выбора в localStorage (минимальный JS).

  Ожидаемый результат: сайт автоматически адаптируется под тему ОС.

9.2.2. ХЛЕБНЫЕ КРОШКИ (BREADCRUMBS)

  Навигационная цепочка под шапкой: «Главная › Сети › Глава 3».
  Помогает пользователю понять, где он находится в структуре курса,
  и быстро вернуться на уровень выше.

  Компонент: <nav class="breadcrumbs" aria-label="Навигация по сайту">
    - Flexbox-строка с разделителями «›»
    - На мобильных — обрезается до 2 последних уровней
    - Ссылки — обычные <a>, текущий элемент — <span aria-current="page">

  Где использовать: на всех главах курса и внутренних страницах.

9.2.3. АНИМАЦИЯ ПОЯВЛЕНИЯ СЕКЦИЙ

  Секции плавно появляются при попадании в зону видимости —
  это делает прокрутку «живой» и подчёркивает структуру материала.

  Реализация без JavaScript:
    - @keyframes fadeInUp { from { opacity: 0; transform: translateY(20px); }
      to { opacity: 1; transform: translateY(0); } }
    - animation-delay рассчитывается вручную для каждой секции
      (0s, 0.1s, 0.2s…)
    - Обёртывается в @media (prefers-reduced-motion: no-preference),
      чтобы не раздражать пользователей с вестибулярными расстройствами

  Улучшенная версия (с минимальным JS):
    - IntersectionObserver отслеживает появление секций
    - Класс .is-visible навешивается, когда секция попадает в viewport
    - Анимация запускается ровно один раз, без перезапуска при скролле вверх

9.2.4. ПРОДАКШЕН-СТИЛИЗАЦИЯ ФОРМЫ

  Доведение страницы auth.html до уровня «не стыдно показать в портфолио»:
    - Плавная подсветка label при фокусе на поле
    - Иконки внутри input (email, пароль, «показать пароль»)
    - Индикатор силы пароля (слабый / средний / сильный)
    - Состояния «загрузка» и «успех» на кнопке
    - Красивое сообщение об успехе / ошибке сервера
    - Плавный переход между «Вход» и «Регистрация» (сейчас — резкий
      через :target), можно добавить slide-анимацию
    - Кнопки соцсетей-заглушек (в будущем — OAuth)

9.2.5. БОКОВАЯ ПАНЕЛЬ (ASIDE) С ОГЛАВЛЕНИЕМ

  Ключевое улучшение навигации по длинным главам. Слева (на десктопе)
  появляется липкая панель с оглавлением текущей главы: список
  параграфов, каждый — якорная ссылка.

  Что даёт пользователю:
    - Не нужно скроллить наверх — все разделы под рукой
    - Видно, где он находится (активный пункт подсвечивается)
    - Плавный переход по якорю (scroll-behavior: smooth уже есть)

  Технически:
    - <aside class="toc"> внутри <main>
    - position: sticky; top: 90px — «прилипает» при скролле
    - Flexbox-раскладка: <aside> + <article> рядом
    - На мобильных — выдвижная панель (drawer):
        - Скрыта по умолчанию за пределами viewport (translateX(-100%))
        - Кнопка «Содержание» в шапке открывает её через checkbox hack
        - Плавные transition по transform
        - Затемняющий оверлей позади панели

  Ожидаемый результат: страницы курса превращаются в «документацию»
  уровня современных docs-сайтов (как MDN или GitBook).

9.3. ЭТАП 2. ПЕРЕХОД НА PHP
--------------------------------------------------------------------------------

9.3.1. АРХИТЕКТУРА

  Проект переводится с набора статических HTML-файлов на шаблонную
  систему с общим layout и динамическими страницами.

  Ожидаемая структура:

    project-root/
    ├── public/                 Корень веб-сервера
    │   ├── index.php           Единая точка входа
    │   ├── assets/             CSS, JS, изображения
    │   └── uploads/            Загруженные пользователями файлы
    ├── app/
    │   ├── controllers/        Логика страниц
    │   ├── models/             Работа с БД
    │   ├── views/              Шаблоны (layout, partials, страницы)
    │   └── helpers/            Утилиты (auth, validation, flash)
    ├── config/                 Настройки БД, окружения
    ├── storage/                Логи, кэш, миграции
    └── README.txt

9.3.2. ШАБЛОНИЗАЦИЯ

  Общие элементы (header, footer, aside, breadcrumbs) выносятся
  в отдельные подключаемые файлы:
    - app/views/partials/header.php
    - app/views/partials/footer.php
    - app/views/partials/breadcrumbs.php

  Контент глав — в шаблонах глав (views/chapters/*.php) или, что гибче,
  в базе данных: страницы редактируются через админку без правки кода.

9.3.3. КОНФИГУРАЦИЯ И БЕЗОПАСНОСТЬ

  Минимальный набор практик, обязательных с первого дня:
    - Отдельный файл .env с настройками БД (не в Git!)
    - PDO с подготовленными запросами (никаких ручных конкатенаций SQL)
    - CSRF-токены для всех POST-форм
    - Хеширование паролей через password_hash() / password_verify()
    - Валидация и санитизация входных данных на сервере
    - Защита от XSS через htmlspecialchars() при выводе
    - Разграничение прав (гость / пользователь / модератор / админ)

9.4. ЭТАП 3. ФУНКЦИОНАЛ НА PHP
--------------------------------------------------------------------------------

9.4.1. АДМИНИСТРАТИВНАЯ ПАНЕЛЬ

  Отдельный защищённый раздел /admin, доступный только пользователям
  с ролью «администратор».

  Возможности:
    - Управление контентом глав: редактирование текста (WYSIWYG или
      Markdown), вставка/замена изображений, изменение порядка разделов
    - Управление пользователями: просмотр, изменение ролей, блокировка,
      удаление
    - Управление комментариями и темами форума
    - Системные настройки: название сайта, описание, контакты, цвета
      темы, логотип
    - Журнал действий (audit log): кто, что и когда менял
    - Резервные копии БД одной кнопкой

  UI: тот же стиль, что и публичная часть — единый CSS, никакого
  «админского вида». Переходы, карточки, формы — как везде.

9.4.2. ЛИЧНЫЙ КАБИНЕТ ПОЛЬЗОВАТЕЛЯ

  Раздел /account, доступный авторизованным пользователям.

  Возможности:
    - Загрузка и обрезка аватара (например, через GD или Imagick)
    - Смена никнейма с проверкой на уникальность
    - Смена email с подтверждением по ссылке
    - Смена пароля с вводом текущего
    - Просмотр своей активности: комментарии, темы, прогресс по главам
    - Настройки приватности (виден ли профиль другим)
    - Удаление аккаунта с подтверждением

  Прогресс по главам:
    - Таблица user_progress: user_id, chapter_id, completed_at
    - На странице главы — кнопка «Отметить как прочитанное»
    - В личном кабинете — красивый прогресс-бар «Пройдено 5 из 9 глав»

9.4.3. ФОРУМ ОБСУЖДЕНИЙ

  Современный форум, вдохновлённый Reddit, Discourse и Habr —
  в противовес архаичным имиджбордам.

  Ключевые принципы:
    - Уважение к пользователю: аватар, ник, репутация, подпись
    - Дерево обсуждений (nested comments), а не плоская лента
    - Markdown-разметка в постах и комментариях
    - Загрузка изображений с превью и оптимизацией
    - Реакции (лайк, полезно, спасибо) вместо «плюсов и минусов»
    - Модерация через жалобы + автоматические фильтры

  Сущности БД:
    - boards        — доски (разделы форума: Linux, Windows, Сети, DevOps…)
    - threads       — темы внутри досок
    - posts         — сообщения внутри тем
    - comments      — комментарии к постам (с parent_id для дерева)
    - reactions     — реакции пользователей на посты и комментарии
    - attachments   — прикреплённые файлы (изображения, документы)
    - reports       — жалобы на контент

  Функции:
    - Создание доски — только админ
    - Создание темы — любой авторизованный пользователь
    - Ответы, цитирование, упоминания через @nickname
    - Закрепление тем, закрытие темы модератором
    - Поиск по темам и постам
    - Уведомления: «вам ответили», «вас упомянули»
    - Подписка на тему (email или внутреннее уведомление)
    - Сортировка: по новизне, по популярности, по активности
    - Пагинация (без бесконечного скролла — он пугает часть аудитории)

  UI-принципы:
    - Никаких «бампов» и анонимных постов
    - Аватары у всех, у модераторов — специальный бейдж
    - Кнопка «Пожаловаться» — везде, где есть контент
    - Счётчики репутации — прозрачные (видно, за что начислено)

9.5. ЭТАП 4. ПРОДВИНУТЫЕ УЛУЧШЕНИЯ

9.5.1. КОНТЕНТ И ОБУЧЕНИЕ
    - Поиск по всему сайту (по главам, комментариям, форуму)

9.5.2. УВЕДОМЛЕНИЯ И ПОДПИСКИ

9.5.3. СОЦИАЛЬНЫЕ ФУНКЦИИ

    - Достижения: «Прочитал все 9 глав», «Ответил на 50 вопросов»

9.5.4. ПРОИЗВОДИТЕЛЬНОСТЬ И SEO
    - Кэширование страниц (файловое или Redis)
    - Минификация и объединение CSS/JS при сборке
    - Lazy-loading изображений (loading="lazy" — уже сейчас)
    - Оптимизация изображений: WebP + srcset
    - Sitemap.xml и robots.txt
    - Open Graph и Twitter Cards для красивых превью в соцсетях
    - Schema.org разметка для статей (курс — образовательный контент)

9.5.5. БЕЗОПАСНОСТЬ И НАДЁЖНОСТЬ
    - Двухфакторная аутентификация (TOTP: Google Authenticator, Authy)
    - Rate-limiting на формы входа и регистрации
    - Логирование попыток входа и подозрительной активности
    - Автоматические бэкапы БД по расписанию
    - Защита от брутфорса через fail2ban-подобную логику
    - Content Security Policy (CSP) для защиты от XSS

9.5.6. ИНФРАСТРУКТУРА РАЗРАБОТКИ
    - Git-репозиторий с осмысленными коммитами
    - Миграции БД (Phinx, Doctrine Migrations)
    - Юнит-тесты (PHPUnit) для критичной логики
    - Docker-compose для локального окружения (PHP + MySQL + phpMyAdmin)
    - CI/CD через GitHub Actions: линтеры, тесты, деплой
    - Staging-окружение отдельно от продакшена

9.5.7. МЕЖДУНАРОДИЗАЦИЯ
    - Мультиязычность: русский + английский (gettext или свой слой)
    - Переключатель языка в шапке
    - Хранение переводов в отдельных файлах локалей

9.5.8. МОБИЛЬНОЕ ПРИЛОЖЕНИЕ / PWA
    - Превращение сайта в PWA: манифест, service worker, офлайн-режим
    - Возможность «установить» сайт на телефон как приложение
    - Push-уведомления о новых главах и ответах в форуме

9.5.9. АНАЛИТИКА
